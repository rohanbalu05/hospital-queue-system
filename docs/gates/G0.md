## Schema (`db/migrations/0001_init.sql`)

27 tables. Separate lifecycles: `appointments`, `capacity_allocations` (reserved/consumed/released), `visits`, `queue_entries`, `queue_decisions`, `documents`, `ocr_drafts`, `instructions` + `instruction_versions`, `follow_up_tasks`, `conversations` + `messages`. Support: `idempotency_records`, `audit_events`, `outbox_events`, `jobs`, `notifications`, `service_estimates`, `auth_sessions`, `staff_assignments`, `queue_policies`.

Table 13 enforcement:

| Invariant | Enforcement |
| --- | --- |
| One queue entry per visit | `UNIQUE (visit_id)` on `queue_entries` |
| One attendance per appointment | partial unique `visits(appointment_id) WHERE appointment_id IS NOT NULL` |
| One active doctor allocation | `UNIQUE (doctor_id) WHERE state IN ('called','in_service')` on `queue_entries` + doctor row lock (D-005) |
| Capacity never oversubscribed | `session_capacity` guard row (CHECK reserved ≤ capacity) locked after doctor and session; allocation rows in the same tx |
| Queue candidate lookup | index `(session_id, state, eligible_at)` |
| Staff work due | index `(owner_id, status, due_at)` |
| Repeated requests | PK `(actor_id, operation, idem_key)` + `request_hash` + stored response |
| Document/message ownership | FKs to `patients`; server-side checks in every route |

Extra guards: instruction versions are immutable by trigger (only current → superseded); assistant `answered` messages must cite ≥1 version; `escalated` must reference a task; resolved tasks need a disposition; `return_booked` needs the appointment.

## UI direction (from the hospital-ui skill)

Hospital wayfinding signage: calm near-monochrome surfaces (paper #F6F7F4, ink #16232B), colour only for queue meaning (A appointment blue, W walk-in amber, P priority red, aging purple, done green), always with the letter or word. Atkinson Hyperlegible everywhere with tabular figures. Tables and lanes, not card grids. Dense staff screens, spacious patient screens (390 px first), a waiting-room TV display readable from 8 m showing tokens only. Every async view has loading / empty / error / stale states; booking and call-next by keyboard.
